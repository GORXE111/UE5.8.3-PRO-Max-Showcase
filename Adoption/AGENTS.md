# AI 接入作业说明

本目录负责 UE 获取、环境预检和发行框架接入。进入用户的游戏仓库时先读取该仓库的工程规则。

1. 读取 [接入指南](README.md)、[运行时手册](RUNTIME.md) 和 [网络手册](NETWORK.md)。将引擎、工具链、项目、目标平台、渠道与产物范围写入本次接入记录。将示例值保留为待配置，直到拿到真实的测试环境参数。
2. 让用户在 Epic 官方渠道完成账号绑定和授权。以用户明确指定的本地目录运行预检。先使用已验证的基础设施提交和新目录跑离线演示。把环境预检、离线夹具和真实 UE 构建分别记账。
3. 用 `Start-UEAdoption.ps1 -EngineRoot <路径> -Project <uproject> -Platform <平台>` 清点真实项目和引擎的静态输入。保留 `projectIntegration.checks`，按缺项接入构建、Cook、启动就绪和存档迁移适配器。配置项目身份、兼容版本与平台隔离的开发信任根。首次用空白工程和测试存档跑完整路径。玩家存档的验证使用可恢复副本。
4. 可先运行 `Invoke-Win64PackageSmoke.ps1 -VerifyNativeAssetUpdate`，验证三套 Win64 EXE 和 Cook 资产配套切换、签名错配拒绝及故障回退。复用三份包运行[本机 HTTPS 验收](README.md#复用包体验收本机-https-更新)，再用实际游戏和独立渠道验证错误签名、资源缺失、断网、启动超时、迁移失败和恢复。每次保留平台、基包、候选、签名身份、日志以及实际验收范围。真实 UE 进程完成项目定义的就绪才写启动确认。
5. 公网阶段以明确的域名、部署权限和回退方案为前置条件。先做只读 DNS、证书和源站检查，再在测试环境配置 CDN、限流与公开下载路径。发布账号、源站网络和签名私钥采用不同权限，配置记录仅引用密钥位置或环境变量名称。
6. 对照平台分发政策确定 Android 更新范围。PC 与 Android 分别记录安装、签名校验、资源挂载、存档迁移和回退结果。由外网机器以发布计划中的大小与摘要运行 `Test-Download.ps1`，并保留发布器整批校验记录。通过真实外网完整 GET 和 SHA-256 校验后再切换测试渠道。

交付时按真实完成的最高阶段报告。对缺失的项目适配器、发布条件或设备验证给出具体下一步。
